# Кто это? 🎭

Мини-игра для компании: каждая участница тайно пишет несколько фактов о себе,
потом факты перемешиваются и все угадывают, кому что принадлежит. За каждый
верно угаданный факт — балл. В конце — таблица результатов и разбор.

Каждая играет со **своего телефона** под своим именем, всё синхронизируется
в реальном времени. Ведущий не нужен.

## Как это работает

- Статический сайт (HTML + CSS + JS, без сборки).
- Синхронизация между устройствами — через **Firebase Firestore** (бесплатный
  тариф Spark, карта не нужна).
- Деплой — GitHub Pages (или Vercel / Netlify, всё статика).

```
index.html               разметка
styles.css               стили
app.js                   вся логика игры
firebase-config.js       твой ключ Firebase (вставить значения)
firebase-config.example.js  шаблон конфига
firestore.rules          правила доступа к базе
.github/workflows/       авто-деплой на GitHub Pages
```

## Настройка Firebase (один раз, ~5 минут)

1. Открой <https://console.firebase.google.com> → **Add project**.
   Имя любое, Google Analytics можно выключить.
2. В проекте: **Build → Firestore Database → Create database** →
   выбери **Start in test mode**, регион любой (например `eur3`).
3. На главной проекта нажми иконку **`</>`** (Web app), зарегистрируй
   приложение (имя любое, Firebase Hosting включать не нужно).
4. Firebase покажет блок `const firebaseConfig = { ... }`.
   Скопируй эти значения в **`firebase-config.js`** вместо `"ВСТАВЬ_СЮДА"`.
5. (Рекомендуется) На вкладке **Firestore → Rules** вставь содержимое
   `firestore.rules` и опубликуй — это ограничит доступ только коллекцией
   комнат.

> **Про ключ:** значения в `firebaseConfig` не секретные — Firebase отдаёт
> их каждому браузеру по дизайну. Поэтому их можно спокойно коммитить.
> Защита строится на правилах Firestore, а не на скрытии ключа.
> Если всё же не хочешь его светить — сделай репозиторий приватным.

## Деплой на GitHub Pages

1. Создай репозиторий на GitHub и запушь туда содержимое этой папки:
   ```bash
   git init
   git add .
   git commit -m "Кто это — игра"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```
2. В репозитории: **Settings → Pages → Build and deployment → Source:
   GitHub Actions**.
3. Workflow из `.github/workflows/deploy.yml` соберёт и опубликует сайт
   автоматически. Через минуту-две получишь ссылку вида
   `https://USERNAME.github.io/REPO/`.

Раздай подругам эту ссылку + код комнаты — и играйте.

### Альтернатива без Actions

Можно и проще: **Settings → Pages → Source: Deploy from a branch →
main / root**. Тогда workflow не нужен, GitHub просто отдаёт файлы как есть.

### Ещё проще (без GitHub)

Перетащи всю папку на <https://app.netlify.com/drop> — получишь ссылку
сразу, без git и аккаунта.

## Локальный запуск

Из-за ES-модулей `file://` не годится — нужен локальный сервер:

```bash
python3 -m http.server 8000
# открой http://localhost:8000
```

## Настройки игры

- При создании комнаты выбирается **режим**:
  - **Свободный режим** — каждая пишет факты в свободной форме, число (2–5)
    задаётся при создании.
  - **Вопросы к девичнику** — все отвечают на один и тот же набор из 9 вопросов
    (guilty pleasure, странная привычка, нелепая покупка и т.д.); при угадывании
    ответ показывается вместе со своим вопросом.
- Минимум 2 участницы.
- Свои факты при угадывании автоматически пропускаются.
- Игра переходит к результатам, когда **все** ответили на все факты.
