# HANDOFF — «Кто это?» (kto-eto)

Документ для передачи проекта новой сессии (Claude Code). Описывает то, что
не очевидно из чтения кода: зачем, модель данных, состояние деплоя, инварианты.

## Что это

Мини-игра для компании (6–10 подруг). Каждая тайно пишет N фактов о себе,
факты перемешиваются, все по очереди угадывают, кому принадлежит каждый факт.
За верную угадку — балл. Разовое развлечение на вечер, не продукт.

Ключевое требование заказчика: каждая играет **со своего телефона** под своим
именем, синхронно, **без ведущего**. Должно работать в РФ (отсюда Firebase +
GitHub Pages — обычно доступны).

## Текущий статус

**Готово и задеплоено, играбельно.** Реализованы правки:
- Ролевое лобби (создательница видит код + кнопку «Начать»; присоединившиеся —
  список участниц со статусами и «ждём начала»).
- Пошаговый синхронный геймплей: по одному факту, единый перемешанный порядок,
  ждём ответа всех → показываем правильный ответ → «Дальше». Свой факт тоже
  показывается (наблюдаешь, пока другие угадывают).
- **Устойчивость к рефрешу**: личность (`me`+код) хранится в `sessionStorage`,
  при перезагрузке `tryRestore()` переподключает к комнате и возвращает на нужный
  экран. Полностью закрытая вкладка → ручной перезаход по коду в фазе игры (join
  пускает существующую участницу обратно).
- **Кнопка создательнице «показать ответ»** на шаге — разлочивает зависший шаг,
  если кто-то отвалился и не отвечает.
- **Защита от одинаковых имён** в лобби (иначе коллизия id фактов/голосов).
- **Разбор голосов на результатах**: под каждым фактом — кто за кого голосовал
  (угадавшие зелёным, первыми) + счётчик «угадали N из M».

## Архитектура

Статический сайт (vanilla HTML/CSS/JS, ES-модули, без сборки) + **Firebase
Firestore** как единственный бэкенд для синхронизации между устройствами.
Реалтайм — через `onSnapshot`. Своего сервера нет.

```
index.html                 разметка (секции-экраны, переключаются классом .hidden)
styles.css                 стили (тёплая «квартирная» палитра, CSS-переменные)
app.js                     вся логика (ES-модуль, делегирование событий)
firebase-config.js         web-конфиг Firebase (закоммичен — он не секретный)
firebase-config.example.js шаблон
firestore.rules            правила: доступ только к коллекции rooms
.github/workflows/deploy.yml  авто-деплой на GitHub Pages
README.md                  инструкции по настройке/деплою
```

## Модель данных (Firestore)

Коллекция `rooms`, id документа = код комнаты (напр. `ЛУНА42`).

```js
{
  code: "ЛУНА42",
  factCount: 3,                 // 2–5, задаётся при создании
  phase: "lobby" | "playing" | "results",
  creator: "Настя",            // имя создательницы (для ролевого лобби)
  players: [ { name: "Настя", ready: false }, ... ],
  facts:   [ { id: "Настя__0", text: "...", owner: "Настя" }, ... ],
  guesses: { "Лена": { "Настя__0": "Оля", ... }, ... },  // ответы каждой
  order:   ["Настя__1","Оля__0", ...],   // ПЕРЕМЕШАННЫЙ список factId
  stepIndex: 0,                 // текущая позиция в order
  stepRevealed: false,          // показан ли правильный ответ текущего факта
  createdAt: <serverTimestamp>
}
```

`order` — единый источник правды о последовательности. Пишется один раз при
старте (`beginGame`, Fisher-Yates shuffle). Порядок НЕ пересчитывается на
клиентах — все читают один и тот же `order` из документа.

## Поток игры

1. **createRoom** → phase `lobby`, кладёт creator + себя в players.
2. **joinRoom** (только в фазе lobby) → добавляет себя в players.
3. **submitFacts** → пишет свои факты (`{id, text, owner}`), ставит `ready: true`.
4. **beginGame** (в UI — только создательница) → shuffle `facts→order`,
   phase `playing`, сброс stepIndex/stepRevealed, очистка guesses.
5. **renderPlay** (на каждый snapshot): показывает факт `facts[order[stepIndex]]`.
   - `required` = все игроки, кроме владельца факта.
   - когда все `required` ответили → `triggerReveal` ставит `stepRevealed: true`.
   - «Дальше» → `nextFact`: `stepIndex+1` (или phase `results` на последнем).
6. **showResults** → балл за каждый `guess`, где ответ == owner; таблица + разбор.

## Инварианты / на что не наступить

- **Владелец исключён из `required`** → шаг не ждёт автора факта, дедлока нет.
  Автор при этом видит свой факт (пометка «Твой факт») для сохранения темпа.
- **reveal и advance идемпотентны** (last-write-wins). Несколько клиентов могут
  записать одно и то же значение — состояние сходится. `triggerReveal` ещё и
  защищён локальным `revealSent`, чтобы не спамить записи.
- **Варианты ответа исключают только `me`**, но НЕ владельца — владелец и есть
  правильный ответ, его нельзя убирать из кнопок.
- **`me` персистится в `sessionStorage`** (ключ `ktoeto:v1`), в памяти хранится
  тоже. `tryRestore()` на загрузке переподключает к комнате; `routeInitial(data)`
  ставит на экран по фазе. `sessionStorage` живёт до закрытия вкладки → рефреш
  переживается автоматически, полное закрытие → ручной перезаход. `clearSession()`
  вызывается на «Сыграть заново» и когда комната пропала/в фазе `results`.
- **Скип шага (создательница)**: `skipStep()` пишет `stepRevealed: true` в обход
  ожидания всех — размораживает зависший шаг. Кнопка видна только создательнице
  и только пока шаг не раскрыт.
- **Reconnect в фазе `playing`** разрешён только уже существующей участнице
  (по имени); новых игроков join по-прежнему не пускает. В лобби join под уже
  занятым именем блокируется тостом — защита от коллизии id фактов/голосов.
- Экраны — это `<section>` с классом `.hidden`; `go(id)` показывает нужный.
  Вся навигация — через `data-action` + одно делегирование в конце app.js.

## Деплой (текущее состояние)

- **GitHub**: репозиторий `Razer15/kto-eto`, публичный, ветка `main`.
- **Pages**: Source = GitHub Actions; workflow `deploy.yml` публикует при пуше.
- **Live**: `https://razer15.github.io/kto-eto/`
- **Firebase**: проект `devichnik`, план Spark (бесплатный, без карты).
  Лимитов Spark хватает с колоссальным запасом для игры на компанию.
- `firebase-config.js` закоммичен намеренно: web-конфиг Firebase публичен по
  дизайну (уходит в браузер каждому). Защита — на правилах Firestore.
- Обновление сайта: пуш в `main` → Actions передеплоит за 1–2 минуты.

## Известные ограничения

- **Зависший клиент**: если кто-то закрыл вкладку посреди игры, шаг ждёт её
  ответа. Снимается двумя путями — перезаход по коду (reconnect) ИЛИ кнопка
  создательницы «показать ответ» (`skipStep`). Уже не блокирующее ограничение.
- **Правила Firestore в test mode истекают ~через 30 дней**. Чтобы не сломалось,
  опубликуй `firestore.rules` (Firebase → база → Rules → Publish). На момент
  передачи — проверить, опубликованы ли они (заказчик мог не дожать этот шаг).
- **ES-модули**: локально нужен http-сервер (`python3 -m http.server`),
  `file://` не работает из-за CORS на import.
- Предупреждение в Actions про «Node.js 20 deprecated» — косметика, не ошибка.

## Как проверить, что всё живо

Открыть live-URL: должен быть главный экран с кнопками «Создать игру / Войти по
коду». Если вместо него «Почти готово / нужна настройка» — не подхватился
`firebase-config.js` (плейсхолдеры или файл не задеплоился).
